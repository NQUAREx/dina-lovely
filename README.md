# Сад, где живёт любовь

Законченная маленькая романтическая игра для браузера. Godot 4.7.2, GDScript, Compatibility renderer, однопоточный WebAssembly. Без серверной части и внешних запросов. Исходники находятся в корне, готовый экспорт — в `docs/`.

## История и управление

Четыре последовательные главы: садовый лабиринт с тремя письмами и двумя секретами; три волны добрых хранителей; выращивание шести цветов; финальный сундук с шифром и открыткой. Ориентир — 10–15 минут неспешного прохождения с чтением; скорость зависит от игрока.

- ПК: WASD / стрелки, мышь для направления атаки, ЛКМ / пробел для атаки, E для действия, Esc для меню.
- Телефон: проведите пальцем в левой части экрана для движения; кнопки справа — действие и атака. Атака автоматически выбирает ближайшего хранителя.
- Основная ориентация — горизонтальная. В вертикальной появляется просьба повернуть устройство.
- Журнал писем и звук доступны из меню. Поражение возвращает к началу боевой комнаты, письма остаются.

## Персонализация подарка

Редактируйте UTF-8 файл `content/letters.json`. Поля `recipient`, `signature`, `card_title`, `card_text`, `photo`, `photo_caption` задают открытку. В `letters` находятся `id`, `title`, `text`, необязательный `image` каждого письма. Используйте `\n` для переноса строки. Не меняйте ID: они связаны с логикой игры.

Положите совместное фото в `assets/photo.jpg` и укажите `"photo": "res://assets/photo.jpg"`. Затем повторите экспорт. По умолчанию используется оригинальная иллюстрация пары на скамейке; это не ваша фотография. Для необязательной иллюстрации письма аналогично задайте путь `res://assets/имя.png`. Фото никогда не отправляется на сервер во время игры, но при публикации весь статический сайт, включая фото и тексты, будет публичным.

Финальный порядок: **Солнце → Цветок → Звезда**. При переписывании писем сохраните эти подсказки либо измените порядок в `scripts/game.gd`.

## Открыть проект

Установите [Godot 4.7.2 Standard](https://godotengine.org/download/archive/4.7.2-stable/) и соответствующие официальные Export Templates. Импортируйте `project.godot`, нажмите F6/F5. C# и дополнительные плагины не нужны.

```bash
godot --path . --editor
```

В Ubuntu внутри Termux/proot используйте `tools/godot.sh` вместо прямого вызова. Скрипт собирает маленький process-local shim для `scandir64`: при отказе доступа к `/dev` он инициализирует указатель результата, предотвращая native crash редактора. Этот обход нужен только локальному инструменту, в браузерную сборку он не входит. Требуется `cc` (`build-essential`). На обычном Linux/macOS/Windows shim не нужен.

```bash
./tools/godot.sh --headless --import
./tools/godot.sh --headless --export-release Web docs/index.html
python3 tools/finalize_web.py
```

В этой рабочей среде редактор установлен в `/root/toolchains/godot/Godot_v4.7.2-stable_linux.arm64`.

## Повторный Web Export

```bash
godot --headless --path . --import
godot --headless --path . --export-release Web docs/index.html
python3 tools/finalize_web.py
python3 -m http.server 8000 --directory docs
```

Откройте `http://localhost:8000`, не `file://`. Если команда называется иначе, замените `godot` полным путём к исполняемому файлу. Preset `Web` уже настроен: Thread Support выключен, PWA и расширения выключены, Compatibility renderer. COOP/COEP и SharedArrayBuffer не требуются. Не включайте потоки при повторном экспорте для GitHub Pages.

Для проверки пути подпапки запустите сервер из родительской папки проекта и откройте `/love-in-bloom/docs/`. Все экспортированные ресурсы используют относительные пути.

## Публикация на GitHub Pages позднее

Репозиторий: https://github.com/NQUAREx/dina-lovely. Публикация настроена из `main`, папки `/docs`. Результаты и ограничения проверки см. `tests/RESULTS.md`.

1. Создайте репозиторий GitHub и добавьте весь проект, включая `docs/`.
2. Отправьте ветку `main`.
3. В Settings → Pages выберите Deploy from a branch → `main` → `/docs` → Save.
4. После завершения публикации откройте `https://USERNAME.github.io/REPOSITORY/`.

Сохраните все файлы экспорта вместе: HTML, JS, WASM, PCK, изображения и служебные файлы. `docs/.nojekyll` отключает обработку Jekyll. Для обновления игры повторите экспорт и commit всей папки `docs/`. Git LFS для необходимых файлов Pages не используйте.

## Сохранения

`user://garden_save_v1.json` сохраняется через файловую систему Godot в браузерном IndexedDB. Запись происходит после каждого письма, секрета, полива, перехода и завершения. Продолжение начинает текущую главу в безопасной точке; незавершённый бой и последовательность финальных знаков начинаются заново. Найденная лейка, вода и цветы сохраняются. Письмо из боевой комнаты отмечает её прохождение.

Прогресс привязан к браузеру, устройству и адресу сайта. Приватный режим, запрет хранилища и очистка данных могут удалить его. Переноса между устройствами нет. Кнопка «Новая игра» просит подтверждение, если уже есть прогресс.

## Структура и производительность

- `scripts/game.gd` — состояния четырёх глав, интерфейс, управление, бой, сохранения и рисование.
- `content/letters.json` — редактируемый романтический контент.
- `assets/atlas.png` — оригинальный пиксельный атлас персонажа, окружения и врагов. Четыре направления, четыре кадра ходьбы.
- `assets/ground.png`, `glow.png` — тайлы и общая текстура мягкого свечения.
- `assets/*.wav` — оригинальные музыка и эффекты.
- `tools/create_assets.py` — воспроизводимый генератор оригинальных ресурсов, требует Python 3 и Pillow.
- `tests/` — проверки состояний и достижимости.
- `docs/` — готовая браузерная сборка.

Рисуются только видимые тайлы и объекты; используется один атлас, ограничение в 130 частиц, простое поведение врагов, до девяти врагов одновременно. Мягкое освещение создано текстурами, без тяжёлых постэффектов. На снижении частоты кадров автоматически уменьшается число второстепенных частиц и светлячков. Pixel art использует Nearest, текст и фото — отдельные настройки.

Цель — 60 FPS, а не обещание для любого устройства. Safari/iOS необходимо проверять на настоящем устройстве: WebGL 2, ограничения памяти и звуковая политика различаются. Музыка запускается после действия игрока. Подробные фактические результаты проверок см. `tests/RESULTS.md`.

## Проверки разработчика

```bash
XDG_DATA_HOME=/tmp/love-in-bloom-test ./tools/godot.sh --headless --script tests/playthrough.gd
python3 tools/serve.py
```

Тест проходит все главы через методы игрового состояния и отдельно проверяет связность лабиринта. Это автоматическая проверка логики, а не замена ручному прохождению. `tools/serve.py` — только локальный статический preview server с gzip; для GitHub Pages он не нужен.

### Браузерная проверка

`python3 tools/build_browser_qa.py` создаёт отдельный проект `../love-browser-qa`, проходящий 51 проверку внутри WebAssembly. Он не публикуется. В production нет тестовых команд или переключения уровней. `tests/firefox_qa.py` проверяет release-интерфейс, IndexedDB, ориентацию и этот отдельный Web QA build. Пути к Firefox и geckodriver в тесте рассчитаны на текущую Linux-среду.

После каждого экспорта запускайте `python3 tools/finalize_web.py`: он добавляет понятную кнопку перезапуска при сетевой ошибке или потере WebGL context. На очистку хранилища браузера этот механизм не влияет.
